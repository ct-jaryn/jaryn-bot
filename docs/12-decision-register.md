## 一、影响架构，P0 前必须定（最贵）

| ID | 决策 | 选项 | 我的建议 | 不定的后果 |
|---|---|---|---|---|
| **D-01** | 使用者范围 | ① 只有你一个人；② 你 + 家人/同事（各自独立 Bot，不共享）；③ 小团队共用（明确不做） | ① 或 ②；② 需要"多实例/多 owner"，架构要预留 | 若以后要 ②，鉴权与数据隔离要返工 |
| **D-02** | 服务端部署在哪 | ① 云 VPS（公网）；② 家里 NAS/旧笔记本（家宽）；③ 公司内网 | ①（省事、通道 webhook 可达）；隐私敏感选 ②+Tailscale | 决定客户端/IM 接入方式，返工成本高 |
| **D-03**（已定） | 入口优先级 | ① IM 优先；② Web 优先 | **② Web 优先**（v0.1 自带 Web UI） | 已决定，无 |
| **D-04** | 模型策略 | ① DeepSeek 云 API；② 本地 vLLM/Ollama；③ 双轨（默认云，可切本地） | ③（架构已支持，默认云） | 影响硬件预算、隐私承诺、评测口径 |
| **D-05** | 云电脑形态 | ① 容器（Docker，秒级）；② microVM（Firecracker，强隔离）；③ 先容器、后 microVM | ③ | 影响隔离强度、运维复杂度、v0.4 工期 |
| **D-06** | 本机出网（已定） | ① 不做；② 做（`jary tunnel`） | **② 支持**，随云电脑交付；客户端必须在线 | 不做则网页任务失败率上升 |
| **D-07** | 默认要不要桌面（GUI） | ① 只做浏览器 + 终端；② 浏览器 + 桌面（Xvfb/VNC） | ①（省 2–3 周，桌面可靠性差） | 少数只有桌面客户端的场景做不了 |
| **D-08** | 开源许可证 | ① MIT；② Apache-2.0；③ 不开源 | ① 或 ②（插件生态友好） | 影响贡献者、插件作者、商业化 |
| **D-09** | 技术栈确认 | ① TypeScript/Node 24（现文档）；② Python worker + TS 网关 | ① | 定错则全部代码重写 |

## 二、v0.1 发布前要定（影响日常体验与成本）

| ID | 决策 | 选项 | 我的建议 | 不定的后果 |
|---|---|---|---|---|
| **D-10** | 通知通道（已定） | — | **暂不做**：v0.1 只 Web 入口 | 无 |
| **D-11** | 审批默认强度 | ① shell 默认 ask、写文件 allow（现文档）；② 更严（写文件也 ask）；③ 更松（shell 白名单自动） | ① | 太严没人用，太松会出事 |
| **D-12** | 后台任务审批 | ① 0 容忍（超时=拒绝）；② 30 分钟同前台 | ①（文档已定） | 无人值守时误放行风险 |
| **D-13** | 预算默认值 | 每任务 $0.20、每日 $3–5、每 Bot 每月上限？ | 每任务 0.20 / 每日 5 / 月 60，可配 | 成本失控或不敢用 |
| **D-14** | 记忆整理策略 | ① 同模型每晚整理；② 便宜小模型；③ 手动触发 | ① 起步，稳定后换 ② | 质量 vs 成本 |
| **D-15** | 会话续聊策略 | ① 同 IM thread 一直续；② 每条消息新会话；③ 超 N 轮自动新会话 | ①（体验），配合压缩 | 成本与"记得住"的平衡 |
| **D-16** | v0.1 是否含多 Bot 名册 | ① 含（P3）；② 先单 Bot，P3 顺延 | ①（这是卖点） | 范围与工期 |
| **D-17** | office 产物 | ① LibreOffice 容器；② 只支持 md/csv；③ 后置 | ①（v0.1 就要 pptx/xlsx） | 用户预期与镜像体积 |
| **D-18** | 日志隐私 | ① 不落完整 prompt（默认）；② 落但 7 天轮转；③ `--debug` 才落 | ① | 调试便利 vs 隐私 |
| **D-19** | 数据保留 | 会话/记忆/产物/审计：30/90/180 天/永久？ | 产物 30 天、审计 180 天、会话与记忆永久（可删） | 磁盘与隐私 |
