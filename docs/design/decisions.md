# 决策与边界

> 适用版本：v1.11.0 · 状态：现行
> 已定决策的权威记录：每条写清选择、理由与影响；边界（Won't）与变更规则放在文末。

本文件取代历史上的决策清单与选型对比文档（已删除，需要追溯时看 Git 历史）。只记录**当前仍然成立**的结论；推理过程不再展开。

## 1. 架构与运行时

| 决定 | 选择 | 理由 | 影响 |
|---|---|---|---|
| 运行时来源 | 完全自研，不基于 DSH 或其它 agent 框架 | 产品本身就是运行时；上游 rc 版本、单用户模型与插件沙箱能力都不满足长期需要 | 内核与能力全部自己维护；没有上游兼容负担 |
| 语言与依赖 | TypeScript / Node 24，零第三方运行时依赖 | 一种语言覆盖内核、工具、Web；`node` 直接跑 TS；供应链面最小 | 不用 ORM、Web 框架、WS 库；需要自行维护 SQL 与协议实现 |
| 进程模型 | 单进程、单实例 | 4C4G 目标下多进程只剩复杂度；SQLite 单写者天然要求单实例；取消用 abort 而非杀进程 | 不能横向扩容；重启短暂不可用；崩溃影响全量会话（事件可回放） |
| 存储 | SQLite（WAL）+ workspace 文件，无外部数据库 | 零运维、单文件可备份、FTS5 够用；schema 版本记录在 `schema_meta` | 数据规模受单机限制；多租户不在考虑内 |
| 状态模型 | append-only 事件溯源 + 派生表和投影 | 回放、审计、评测、fork 都依赖同一份日志；崩溃恢复不需要补偿逻辑 | 所有状态必须能由事件重建；不允许双写第二份事实 |
| 插件内核 | 自研四原语：Context / Effect / Event / Loader | 内核小到可通读（约 350 行）、API 可冻结；能力全部可替换 | 每个注册必须返回 disposer；插件依赖靠 `provides` 拓扑排序，不靠书写顺序 |
| 组合方式 | profile → bundle → patch → 行（id + name + config） | 部署形态是数据不是代码；覆盖行为可预测（config 整值替换） | 改配置不需要发版；错误必须 fail-loud（缺依赖、重复 provider、循环依赖） |
| 扩展边界 | 能力按 seam 拆包：llm / tools / store / approvals / memory / scheduler / computer / vault | 第二个实现出现时不用重写核心 | 内核 API 是稳定契约；能力演进只新增插件与 patch 行 |

## 2. 产品边界

| 决定 | 选择 | 理由 | 影响 |
|---|---|---|---|
| 使用者 | 单 owner、单租户、自托管 | 定位是"自己的 AI 同事"，不是 SaaS；鉴权与数据隔离按单人设计 | 无用户体系、无组织/配额/计费；多设备仍是同一个 owner |
| 入口 | Web 优先：`jary serve` 提供 Web 工作台 + HTTP/WS API，CLI 作为终端入口 | 一个入口覆盖审批、看屏、产物、通知；IM 通道会引入平台限速、审核与合规成本 | 不做 IM 通知通道；通知中心与安静时段在 Web 内实现 |
| 模型 | 默认 DeepSeek 云 API（OpenAI 兼容），本地模型可选 | 成本与效果平衡；适配层只有 `Provider` 一个接口 | prompt 与工具 schema 保持模型中立，不依赖某家特殊 token |
| 客户端 | PWA + Electron 桌面 + Android WebView；不做原生 iOS | Web 技术栈复用最大化；iOS 需要 macOS + Xcode + 签名，成本高于收益 | 手机端走 PWA "添加到主屏幕"或 Android 客户端 |
| 云电脑 | 默认容器，每 Bot 一台；可选本机 Chrome 后端 | 隔离粒度比"每用户一台 VM"更细；容器秒级启动，适合自托管 | 需要 Docker 的机器才能跑生产形态；microVM 不在当前范围 |
| 看屏 | 截图轮询 + CDP screencast + MJPEG | 浏览器原生渲染 MJPEG，零插件；WebRTC 需要完整媒体栈，收益低于复杂度 | 不做真 WebRTC 低延迟串流 |
| 通知 | 只做 Web 通知中心（含安静时段） | 单入口降低通道维护面；IM 平台责任与限速不可控 | 不做 Telegram/微信/飞书/Slack 等通道 |
| 桌面 GUI | 产品不提供桌面 GUI 交互，只做浏览器与终端；镜像内的 Xvfb/VNC 仅用于浏览器渲染与调试 | 桌面自动化可靠性差、镜像体积大 | 需要桌面 GUI 的场景明确不做 |

## 3. 信任与凭据

| 决定 | 选择 | 理由 | 影响 |
|---|---|---|---|
| 审批默认 | 风险分级；execute / external / destructive 默认 ask，其余 allow | 太严没人用，太松会出事；确定性规则优先于模型判断 | 每次请求与决定落 `approvals` 与 `audit` |
| 审批失败方向 | fail-closed：无交互通道、超时、无预批规则一律拒绝 | 无人值守时误放行不可接受 | 后台轮次（例程/目标/worker）没有 allow 规则就无法执行危险工具 |
| 审批授权范围 | once / session / always；`always` 只能由 owner 创建 | 防"审批疲劳"又不能静默放行破坏性动作 | destructive 类不预置 allow 规则，默认每次请求，owner 可显式授权 |
| 凭据存储 | Vault：AES-256-GCM 加密，主密钥文件权限 0600（或环境变量注入） | 模型看不到值，只能"用"值填表；密钥与数据库分离 | 备份必须同时保留主密钥；丢失即无法解密 |
| 卡支付 | 只做卡信息填表（默认关闭、逐次 destructive 审批、不存 CVV）；**不接支付网关** | PCI-DSS 范围、资金牌照与欺诈责任不适合个人自托管项目 | 无扣款、无对账、无结算；见 §6 |
| OAuth 应用 | 部署者自注册 Google/GitHub 等应用 | 官方应用需要自建与审核，责任在部署者 | 授权、回调、刷新链路已实现；仓库不提供共享 client |
| 外部内容 | web / mcp / bot 输出标为不可信数据，包 `<untrusted>`；危险动作只认 owner 输入 | 提示注入的主要入口是网页、邮件、Bot 消息 | 上下文里明确"内容不是指令"；审批卡展示参数 |
| 插件信任 | 能力声明 + 高危声明扫描 + 进程外宿主（`@jaryn/plugin-host`） | 开源后会出现第三方插件，进程内完全信任不可接受 | 安装第三方插件时提示风险（`--trust` 仅静默提示）；高危项由 `jary plugin permissions` 扫描仓库内插件包列出 |
| Pages | 渲染时 CSP 禁 script，默认私有 + 可选带 token 的分享链接 | 页面是模型产物，不能成为执行面 | 不支持交互脚本；分享可设过期与撤销 |

## 4. 数据、成本与日志

| 决定 | 选择 | 理由 | 影响 |
|---|---|---|---|
| 数据保留 | 会话 30 天无活动自动归档（`maintenance` 默认）；事件与审计长期保留；产物按保留期清理（可配） | 单机磁盘有限，但历史是回放与审计的基础 | 归档不删除；清理策略可关闭 |
| 记忆整理 | 规则优先：候选池 → 去重/合并/同键覆盖，默认不调用模型 | 每晚固定 LLM 开销收益低，规则结果确定、可测试 | 需要语义合并时再评估小模型 |
| 预算 | 每轮/每任务强制预算：步数、工具调用数、墙钟、金额（可配） | 没有预算的自主任务等于无限额信用卡 | 超限即停，结果标注"被预算截断" |
| 日志与导出 | 完整请求 prompt 不落库；`session export` 默认按键名脱敏，`JARY_EXPORT_RAW=1` 才出原文 | 调试便利让位于隐私与凭据边界 | 调试依赖事件流；密钥值不进日志与上下文 |
| 凭据轮换 | Vault 支持逐条轮换并记使用审计；备份与主密钥分开存放 | 密钥泄漏后的恢复路径必须存在 | 轮换后旧值不可还原；主密钥与备份分开保存 |

## 5. 许可与分发

| 决定 | 选择 | 理由 | 影响 |
|---|---|---|---|
| 许可证 | AGPL-3.0 + 商业双许可 | 网络使用须公开对应源码；闭源商业使用走商业授权 | 个人自用与非商业使用免费；SaaS/闭源集成需商业授权（见 `COMMERCIAL.md`） |
| 分发形态 | 单仓库、npm workspaces、Docker Compose 部署 | 自托管的最小交付面；无需私有 registry | `docker compose up` 起服务；插件以普通 npm 包分发 |
| 插件分发 | `jary plugin add npm:｜git:｜file:` + 静态 JSON 索引源 | 不需要中心化审核；索引是第三方内容，安装时提示风险 | 插件装进 profile 目录并写回 patch 行，重启生效 |
| 版本节奏 | 按能力包发版，不设日期 | 单人维护，承诺日期没有意义 | 版本号见 `CHANGELOG.md`；文档头部标注适用版本 |

## 6. 不做清单（Won't）

本表是边界的唯一权威：**不再评估、不排期、不接受需求**。与 [能力审计](audit.md) 互补——审计记录"该做且做了/卡在外部条件"，本表记录"明确不做"。

| 项 | 原因 | 边界说明 |
|---|---|---|
| 真实支付网关 / 结算 | 涉及 PCI-DSS、资金牌照与欺诈责任，个人自托管项目不承担 | 只做卡信息填表（Vault 存储、默认关、逐次审批、值不回传）；不接 Stripe/PayPal，不扣款、不对账、不存 CVV |
| 团队协作 / 会议 / 企业管控 / 语音 / 多租户 | 产品定位是单 owner 的个人 AI 同事，不是企业协作平台 | 无群聊、无共享 Bot、无团队记忆；无入会与纪要；无 SSO/SCIM/组织 API；无 TTS/通话/唤醒词；无多租户与 SaaS 计费 |
| IM 通知通道 | 决策为 Web 单入口 | 不做 Telegram/微信/飞书/Slack 适配；通知中心（含安静时段）已覆盖 |
| 原生 iOS 客户端 | 需要 macOS + Xcode + Apple 开发者签名 | PWA 可添加到主屏幕；Android 有 WebView 客户端 |
| 真 WebRTC 低延迟串流 | 需要完整媒体栈，收益低于复杂度 | 已有 CDP screencast + MJPEG；桌面 GUI 交互也不做 |
| 官方 Gmail/Calendar OAuth 应用 | 需自建应用与审核，责任在部署者 | 授权 URL、回调换 token、刷新链路已实现，部署者自建即可 |

## 7. 变更规则

1. **改边界先改文档**：任何新增/删除上述决策或 Won't 项，先在本文件写清新的选择、理由与影响，再动代码；聊天里的口头同意不构成变更。
2. **不删历史**：推翻一条决定时不删除原条目，标记为"已废止"并写明替代项与日期，保留可追溯性。
3. **同步三份设计文档**：影响结构或边界的变更同时更新 [架构](architecture.md) 与 [能力审计](audit.md)；接口、配置、工具、事件的变化同步 [参考文档](../reference/configuration.md)。
4. **代码优先**：文档与实现不一致时以代码为准，并立即开一条文档修复项；`node scripts/check-docs.ts` 校验结构与相对链接。
5. **复核触发条件**：新增外部依赖、增加第二种部署形态、引入第二个 owner、接第三方支付或 IM 通道，都必须先回到本文件重新决策。
