# 03 · 版本与开发节奏

> 状态：**现行**。本文只定义**能力顺序与发版条件**，**不包含任何开发周期/工期估算**。
> 范围见 [00 PRD](00-prd.md)，验收见 [04 测试与验收](04-testing-acceptance.md)，暂缓项见 [12 决策清单](12-decision-register.md)。

---

## 1. 节奏原则

1. **不按日历，按能力包发版。** 一个版本 = 一组能力 + 一组退出 Gate；Gate 全过即发，不过不发。
2. **不承诺日期，只承诺范围。** 文档中的阶段编号（P0–P5、v0.x）是顺序，不是时间。
3. **小步可交付。** 每个阶段结束都可停下来用；不存在"全部做完才有价值"的阶段。
4. **一次只开一个能力包。** 未完成当前包的 Gate，不并行开下一个大包（小修/文档/测试可穿插）。
5. **暂缓项入池，不定日期。** 到需要时从池子里取，取时再补设计；**每次版本评审复核一次**。
6. **延期 = 减范围，不是拖时间。** 范围削减顺序见 §5。

---

## 2. 版本序列

| 版本 | 定位 | 含哪些能力包 | 状态 |
|---|---|---|---|
| **v0.1** | 可每天自用的个人 Agent | 运行时 + Web UI + 记忆 + 例程 + 多 Bot + 插件 | **进行中** |
| **v0.2** | 能操作网页的 Agent | 云电脑（容器、浏览器/终端、看屏接管、任务级快照、本机出网） | 下一阶段 |
| **v0.3+** | 按需扩展 | 从"待定包池"取（§4），一次一个 | 未排期 |
| v1.0（可选） | 个人版完整对标 | v0.1–v0.3+ 全部落地 + 稳定化 | 未排期 |

> 版本号只表达"能力增量"，不代表时间。v1.0 是否发、何时发，由实际需要决定。

## 3. v0.1 能力包（P0–P5）

每个阶段都是"能力 + 退出 Gate"，Gate 定义见 [04 §3](04-testing-acceptance.md#3-阶段-gate不过不进下一阶段)。

| 阶段 | 能力包 | 交付物 | 退出条件（摘要） | 依赖 |
|---|---|---|---|---|
| **P0 骨架** ✅ | 组合能跑、能回放 | kernel、store、agent-core、Fake、CLI、tools-shell | 禁用 shell 后模型看不到；`kill -9` 可回放恢复 | — |
| **P1 真模型** ✅ | 能干真活 | DeepSeek 适配、上下文装配、压缩、工具治理、目录检索 | 能完成"读—改—跑测试"；`/stop` 生效；评测达标 | P0 |
| **P2 Web UI** ✅ | 浏览器里每天用 | 静态资源 + `/ws/client`、流式、审批卡、产物、附件 | Web 打开/刷新/重连正确；审批三路径通过 | P1 |
| **P3 记忆 + 多 Bot** ✅ | 记得住、能分工 | 记忆模块（FTS5、目录检索、≤600 token digest）、名册、任务板、子 Bot | 偏好跨会话生效；两个 Bot 能协作；环路护栏生效 | P2 |
| **P4 主动** ✅ | 不用开口 | scheduler、job、goal、预算、投递、熔断 | 定时简报成功；预算超限停止；熔断可用 | P3 |
| **P5 硬化** | 能给别人部署 | 容器沙箱、MCP、插件管理、指标、备份、安全用例、文档 | 干净机器可部署；安全用例全过；备份恢复演练通过 | P4 |

**v0.1 发版条件**：P0–P5 全部 Gate 通过 + 文档齐全 + 安全清单全过。发版形态：`v0.1.0-alpha`（P2 后）→ `v0.1.0-beta`（P4 后）→ `v0.1.0`（P5 后）。

## 4. v0.2 与待定包池

### v0.2 云电脑（下一阶段）

**能力**：每 Bot 一台容器电脑（浏览器/终端）、看屏与接管、任务级快照/回滚、本机出网（`jary tunnel`）、Bot 自建测试容器（配额）。

**退出 Gate**：见 [07 §10](07-cloud-computer.md) 验收章；4C4G 下内存峰值与休眠策略通过；跨 Bot 隔离与逃逸测试通过。

### 待定包池（不排期，一次取一个）

| 包 | 内容 | 启动条件（示例） |
|---|---|---|
| 桌面/手机客户端 | 设备配对、多端同步、PWA 增强 | 需要脱离浏览器/多设备时 |
| Vault 与凭据 | write-only、填充代理、Secure Form、1Password | 需要自动登录/填表时 |
| 连接器 / 邮箱 / Pages | Gmail/Calendar/GitHub、个人邮箱、可交互产物 | 需要"在你常用工具里干活"时 |
| Initiative / teach-a-task | 主动提议、演示录制转技能 | v0.1 跑顺、想让它主动干活时 |
| 卡支付 | 填卡（默认关、每笔审批） | 明确需要且接受安全审计成本时 |

> 取包时先补该包的设计评审，再进开发；不在本文件里预设时间。

## 5. 范围削减顺序（Gate 逼近时，从下往上砍）

1. Pages / 交互产物
2. 第二个通知/外部集成
3. RSS/邮件触发（只留 cron + webhook）
4. office 产物（先只支持 md/csv/json）
5. 插件索引/市场（只留 `plugin add`）
6. OTel/指标（只留 `/healthz`）
7. 多 Bot 对等总线（L1 必须保留）
8. **绝不砍**：审批、预算、事件回放、记忆 digest、`kill -9` 恢复、Web UI 最小闭环

---

## 6. 发版节奏（流程，不是日历）

```
设计评审 ─► 实现 ─► 自测/契约测试 ─► Gate 检查 ─► alpha ─► 自用观察 ─► beta ─► 稳定化 ─► 发版
                                   └─ 不过：修 or 减范围（§5），不延期
```

- **设计评审**：新能力包先改 PRD/FR/接口，再写代码。
- **Gate 检查**：以 [04 §3](04-testing-acceptance.md#3-阶段-gate不过不进下一阶段) 为准，逐条勾。
- **alpha**：功能闭环，自己每天用；**beta**：外部可用，观察崩溃/成本；**stable**：Gate 全过 + 迁移/备份演练通过。
- **发版后**：记录"已知问题 + 暂缓项"，下一次评审再决定是否取包。

## 7. 里程碑（按能力，不按日期）

| 里程碑 | 判定 |
|---|---|
| M0 组合生效 | 配置禁用某工具 → 模型看不到；事件可回放 |
| M1 能干真活 | CLI/Web 能完成一个真实仓库任务 |
| M2 每天可用 | Web UI 连续自用，无需回终端 |
| M3 记得住 | 偏好跨会话生效；两个 Bot 能协作 |
| M4 不用开口 | 定时任务稳定产出；预算可控 |
| M5 能给别人 | 干净机器部署；安全与恢复演练通过 |
| M6 能操作网页 | 云电脑完成登录/表单/接管/快照（v0.2） |

---

## 8. 并行与人力

- **不按人月估算**；按"可并行工作项"组织：后端、前端、测试、文档可同时推进。
- 多人协作时，按能力包拆分（同一时刻仍只开一个包），用任务板与 Gate 对齐，而不是用日期对齐。
- 兼职/全职只影响"同时推进的项数"，不改变版本定义与 Gate。
