# 17 · 不做的清单（Won't）

> 状态：**现行**（v1.9.0 后）。这是"明确不做"的唯一权威清单：**不再评估、不排期、不接受需求**。
> 与 [14 完成度审计](14-completion-audit.md)（"该做且做了/受外部条件卡住"）互补：14 是欠账，17 是边界。

## 1. 永久不做（Won't）

| 项 | 原因 | 边界说明 |
|---|---|---|
| **真实支付网关 / 结算** | 涉及 PCI-DSS 范围、资金牌照与欺诈责任，个人自托管项目不承担 | **只做"卡信息填表"**：卡号存 Vault（默认关闭 `vault.allowCardPayments`）、每次使用 `destructive` 审批、值不进入模型/日志/截图；**不接 Stripe/PayPal 等网关、不发起扣款、不做对账、不存 CVV** |
| 团队协作（多人、共享 Bot、群聊、团队记忆） | 产品定位是单 owner | 多设备仍是同一个 owner |
| 会议（入会/纪要/实时语音） | 与"个人 AI 同事"主线无关 | — |
| 企业管控（SSO/SCIM/网络策略/组织 API/审计导出） | 无多租户 | 单机审计日志已有（`jary audit`） |
| 语音交互（TTS/通话/唤醒词） | 决策不做 | 文字 + 浏览器通知已覆盖 |
| SaaS 计费 / 多租户 | 自托管单实例 | 许可为 AGPL-3.0 + 商业双许可，不是计费系统 |
| IM 通知通道（Telegram/微信/飞书/Slack 等） | 决策：Web 单入口 | 通知中心（含安静时段）已在 Web 内实现 |
| 官方 Gmail/Calendar OAuth 应用 | 需要自建应用与审核，责任在部署者 | 授权 URL、回调换 token、刷新链路全部已实现，部署者自建应用即可（见 `examples/connectors/oauth.md`） |
| 原生 iOS 客户端 | 需要 macOS + Xcode + Apple 开发者签名 | PWA 可"添加到主屏幕"；Android 有 WebView 客户端 |
| 真 WebRTC 低延迟串流 | 需完整媒体栈，收益低于复杂度 | 已有 CDP screencast + MJPEG（浏览器原生渲染） |

## 2. 需要外部条件才能验证（不是不做，是没条件）

| 项 | 卡在哪 |
|---|---|
| 真实模型评测（10 任务） | 需要 `DEEPSEEK_API_KEY`；`npm run eval` |
| Docker 镜像构建/运行实测 | 需要一台有 docker 的机器；`deploy/README.md` |
| 云电脑桌面镜像（Xvfb/VNC/noVNC）真机验证 | 同上，需要 docker |
| macOS 安装包（.dmg） | 需要可用的 macOS runner；`desktop-macos.yml` 已就绪 |

## 3. 可选增强（可做但未做，不属于承诺范围）

- 记忆语义检索（当前 FTS5 + bigram 已够用）
- Pages 交互脚本（设计上禁用 script，保持 CSP 安全）
- 插件索引签名校验（当前有权限声明扫描 + 进程外宿主）
- 进程外插件宿主的能力代理细粒度限额

## 4. 变更规则

- 本清单内项目如需重启讨论，必须先改本文件并说明新的责任/成本边界，**不能只在聊天里口头同意**。
- 已经做了一半又决定不做的（如卡支付网关），代码保持"填表即止"，不留半成品网关代码。
